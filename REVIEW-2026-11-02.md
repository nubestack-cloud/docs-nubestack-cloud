# Documentation review, 2026-11-02

A review of the NubeStack Cloud customer documentation as Codex left it (commits a918826, c34b2f8
and bd51298), against the product at Nexus commit 069ee210. Findings first; the fixes follow in
the commits after this file.

## Verdict

The content is broadly honest and often detailed, but the site does not read like a mature
cloud's documentation. The theme is fought rather than configured, pages are dense walls of
nested lists, several facts are wrong, and the screenshots carry data the product could not
produce. The site needs a re-founded theme, a clearer structure, a page pattern applied to every
service, corrected facts and regenerated graphics.

## Theme and style

1. **The theme is overridden, not configured.** `documentation.css` (269 lines) restyles the
   header, search, sidebar, tables and typography by hand; `docs.js` adds a screenshot dialog
   and a home-made "method picker"; `main.html` replaces the breadcrumbs and article footer.
   Material's own features that do the same jobs (tabs, sections, path breadcrumbs, linked
   content tabs, image zoom by link) are off.
2. **No brand fonts.** The site uses the system font stack; nothing is self-hosted.
3. **The logo is a PNG** cropped from the website logo; no SVG mark; the favicon is a PNG.
4. **Navigation features missing**: no top tabs, no sections, no annotations, no Mermaid or
   diagram standard, no 404 page of our own, no instant navigation or search sharing.
5. **The home page** is a hand-built HTML layout with an empty screenshot frame (a lazy image
   that never loads in a static preview) and a hand-drawn SVG; it does not use Material grids.
6. **Page furniture fights the content**: a sticky "Show instructions for" bar on every page,
   an "Enlarge" badge on every screenshot and a duplicated breadcrumb.

## Information architecture

1. **Tutorials sit in their own top section** and repeat the service pages (persistent storage
   vs Volumes, recover a volume vs Snapshots, clean up vs Deletion). The owner's structure has no
   tutorials section.
2. **"Tools & access"** mixes native OpenStack access with tools that do not exist yet.
3. **Overlong pages**: Manage instances (2,500 words), Roles and permissions (1,600), Load
   balancers (1,550), Deletion and retention (1,300), Instances (1,250).
4. **The API reference** is a home-made Markdown generator (`scripts/build_docs.py`) producing
   long tables; it is not an OpenAPI renderer and its links use absolute paths.
5. **Labels differ from the console**: "Network map" (console: Network topology), "Native
   credentials" (Cloud credentials), "New API key" (Issue an API key), "Invite member" (Invite
   someone), "Resend" (New link), "Switch certificate" (Change certificates).

## Content: wrong or unsupported

| Where | Finding | Product fact |
|---|---|---|
| Certificates, Load balancers, HTTPS tutorial, Limits | "One certificate per listener; SNI coming later" | Built (spec 070 §12): one default certificate plus up to 10 served by host name |
| Create a project, First instance, Projects and quotas | Default network `app` with `192.0.2.0/24` | Network `default`, range `10.0.0.0/24`; only private ranges, /16 to /28, are accepted |
| Routing, Load balancers | Private addresses from 192.0.2.0/24 | Refused (`range_not_private`, `lb_member_outside_project`) |
| Load balancers | Types "Standard" and "Application" | Type names come from each location's catalog; HTTPS ends only on types that say so |
| Publish a web application | API `user_data` must be base64 | The API takes plain text and encodes it itself |
| Service accounts, API authentication | "Scopes only narrow what a key can do" | Scopes add two opt-in powers: `consoles`, `credentials:mint` |
| Settings | Transfer ownership from the Danger zone | **Members → Make owner**; data export only while closing |
| Quota | "You cannot reduce a limit below current use" | You can, with confirmation; nothing is deleted |
| Deletion and retention | Deleting an instance keeps its volumes | Volumes set to delete with the instance go with it; the dialog lists them |
| Errors | `"type": "about:blank"` | `type` is a URL ending in the code; `retryable` is always present |
| Notifications | Always-sent list | Also includes schedule failures; mail through a real relay is not yet built |
| Several pages | "inventory", "reconcile", "placement" in prose | Customer words: "the list", "keeps the count", "the project's location" |

Missing customer-visible capabilities: enforcing the second factor for everyone (with a grace
period), quota presets and quota requests, the instance menu's Attach/Detach network, Forwarding
and Copy ID, load balancer "Public exposure", certificate roles (default / by host name),
Connection details on Consoles and CLI, `?limit` bounds, the full list of delete refusals.

## Graphics

1. Screenshots show **private addresses the product refuses** (192.0.2.0/24 networks,
   load balancer members on 192.0.2.x), **raw user IDs** in activity tables, and activity rows
   that do not belong to the page (an instance create on a load balancer page).
2. No screenshot of SNI (a listener with several certificates).
3. Diagrams are hand-written SVG tied to the old CSS variables; several duplicate each other.
4. Screenshot text audits (`data/screen-text/`) are useful and stay, regenerated.

## Repository hygiene

1. Node files at the root (`package.json`, `package-lock.json`, `scripts/mkdocs.mjs`,
   `scripts/brand.mjs`, `scripts/sync-api.mjs`, `scripts/check-browser.ts`) that only wrap Python or
   serve the screenshots; `node_modules/` and `artifacts/` left in the tree.
2. `REPORT.md` and `CONTENT_REVIEW.md` are stale and claim things this review corrects.
3. The README leads with history rather than how to set up, serve and build.

## What changes

- Material configured properly: brand palettes for light and dark, self-hosted Inter and
  JetBrains Mono, an SVG mark and favicon, tabs, sections, breadcrumbs, ToC, linked content tabs,
  annotations, admonitions, grids and cards, a 404 page; `extra.css` small and token-based.
- One structure: Home, Get started, Concepts, Services (Compute, Networking, Storage, Security,
  Organization), API, Native access, Tools, Help. Tutorials are folded into Get started and the
  service pages; overlong pages are split.
- Every service page follows one pattern: what it is, before you start, tasks in Console | API
  tabs, how it connects, what blocks a delete, limits and good practice, related pages.
- Facts corrected from the product, SNI documented, customer words throughout.
- The API reference rendered from `openapi/v1.json` by an offline OpenAPI renderer.
- Screenshots regenerated against the portal with a corrected sample world; diagrams redrawn.
- Node tooling confined to `scripts/screens/`; stale reports removed; README rewritten.
